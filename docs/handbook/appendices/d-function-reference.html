Appendix D — Function reference

This appendix is a directory, not a manual. It lists every public function of the toolkit with a one-line description, the languages that have it, and the chapter that explains it. The table is generated from the code by sh tools/docs-tables: the description is the function’s R help title (or, for a Stata-only command, its Stata help title), and a new function without one fails the check. For the argument-by-argument reference, use each language’s own help, described next. For what a function’s note in another language says (a route, a reason), see the coverage matrix.

D.1 Where the per-function reference lives

R — help pages. Every exported R function has a roxygen2-generated help page: ?dw_save after installing the package or devtools::load_all("r"). They are the most complete reference of the three, and worth reading even if you work in Python or Stata, because the behaviour is shared. r/_pkgdown.yml groups the pages into families through each function’s roxygen @family tag, ready for a pkgdown site; none is published yet.

Python — docstrings. Every public function has a docstring and type hints (the package ships py.typed): help(dw_save) after from cso_toolkit import dw_save. There is no generated site. docs/dw_io_python_reference.md and docs/dw_api_python_reference.md are hand-written references for the IO and external-API functions.

Stata — help files. Each command has a .sthlp file next to its .ado in stata/src/: help dw_save. Two internal files sit beside them: _dw_py.ado and dw_stata_helpers.py, the Python helpers that dw_save and dw_collaboration call through Stata’s Python integration.

D.2 Names

Several helpers have two names in both R and Python: a short historical name and a dw_-prefixed alias of the same function (aggregate_data_v2 and dw_aggregate_data_v2, create_profile and dw_create_profile, test_scripts and dw_test_scripts, and so on). The aliases are the same objects, so either spelling works; the table lists each function once, under its short name.

D.4 How to find a function fast

  • You know the name. In R, ?<name>; in Python, help(<name>) after importing it from cso_toolkit; in Stata, help <command>.
  • You know the task but not the name. Scan the “What it does” column above, or read the chapter for the task in Part II or III.
  • You want to know whether a language has a function, and what to do if not. The coverage matrix has the notes behind every dash above.

D.5 Where this appendix comes from

The table is generated, so it cannot drift from the code without the Conformance check failing. Its inputs:

  • r/NAMESPACE, Python’s __all__ in python/src/__init__.py, and stata/src/*.ado: which functions exist where;
  • the roxygen titles in r/R/*.R and the titles in stata/src/*.sthlp: the descriptions;
  • book/_data/coverage.json: the order of rows, the notes, and which chapter documents each function;
  • book/_scripts/gen_tables.py: the generator, run by sh tools/docs-tables.

D.6 Microdata archive (datalib_*)

Access: public — unicef-drp/datalib-unicef (public since 2026-07-27).

This family belongs to datalib, the survey-microdata archive tool — a different data layer from the toolkit’s dw_* surface. It shelves and loads survey microdata under the Z:/datalib* IHSN trees; those deposits never enter the aggregate warehouse 060.DW-MASTER. It is documented in full in Part V, and appears here only as a directory entry so the two contracts can be found in one place. As of datalib v0.7.0 / contract v1 the surface is thirteen datalib_* functions: Stata and Python export all thirteen; R exports the thirteen canonical names.

Function R Python Stata Notes
datalib_config ✅ ✅ ✅ Load the per-operator config block (the datalib: root key in ~/.config/user_config.yml). Python also exports the verbatim alias getuserconfig; Stata keeps getuserconfig as the original command
datalib_root ✅ ✅ ✅ Resolve the library root (explicit arg → DATALIB_ROOT → language option → config key → error)
datalib_countries ✅ ✅ ✅ Enumerate country folders under a root
datalib_surveys ✅ ✅ ✅ Enumerate survey folders for a country (exact *_<SURVEY> suffix match, never substring)
datalib_vintages ✅ ✅ ✅ List master vintages; “latest” is the numeric maximum (v10 > v09)
datalib_adaptations ✅ ✅ ✅ List adaptation vintages of a collection
datalib_resolve ✅ ✅ ✅ Resolve country / year / survey / collection to a verified vintage folder

D.6.1 Where the per-function reference lives

datalib documents itself in the same three idioms as the toolkit. R — roxygen2 man pages for the thirteen canonical names; open one with ?datalib_resolve. Python — per-function docstrings (help(datalib_resolve) after from datalib import datalib_resolve) plus the CLI entry point python -m datalib. Stata — help datalib, and a companion .sthlp file next to each command’s .ado.

This family is tracked in its own repository, unicef-drp/datalib-unicef, not in this book’s source tree; the coverage-matrix appendix’s datalib note is the authoritative pointer to it. Because datalib is a tier-(ii) ecosystem package (see The UNICEF analytics ecosystem), its cross-language coverage is asserted and tested in that repository, not in this appendix.
