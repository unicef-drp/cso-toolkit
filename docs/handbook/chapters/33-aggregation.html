7  Aggregation

Aggregation is the step where many country-level observations collapse into a few regional or global numbers. It is also where most reproducibility bugs hide: an unweighted mean where a population-weighted one was intended, a “global” figure built from countries that hold a third of the world’s children, a regional rate that silently dropped every country missing the denominator. The aggregation contract exists to make these decisions explicit, auditable and the same in every language a sector team uses.

The contract has two layers. At the bottom sits aggregate_data_v2(), a grouped aggregator that returns each value together with the coverage figures needed to judge whether it can be trusted. On top sit helpers, each pairing one recurring problem with one function: apply_time_window() picks the latest observation in a window, dw_nestweight() redistributes weights over missing rows, dw_pop() fetches population denominators and dw_regions() produces UNICEF regional aggregates. generate_agg_footnote() turns the coverage figures into the caption that travels with the result.

7.1 The core aggregator: aggregate_data_v2

Languages: R, Python. Stata: n/a. See the coverage matrix.

aggregate_data_v2() takes a long data frame, one observation per row, and returns one row per group, a group being defined by the by columns. Each output row carries the aggregated value and a configurable set of coverage columns. Rows with a missing value in any by column are dropped before grouping.

The arguments match across the two languages apart from spelling. Python makes everything after by keyword-only, renames global to global_, and turns R’s dotted flags (pop.coverage) into underscored ones (pop_coverage).

  • R
  • Python
agg <- aggregate_data_v2(
  data,
  value  = "OBS_VALUE",
  weight = "population",
  by     = c("INDICATOR", "TIME_PERIOD"),
  method = "weighted_mean",
  coverage_threshold = 0.5
)
agg = aggregate_data_v2(
    data,
    value="OBS_VALUE",
    weight="population",
    by=["INDICATOR", "TIME_PERIOD"],
    method="weighted_mean",
    coverage_threshold=0.5,
)

7.1.2 Methods

Pick the method to match the kind of indicator, because each method encodes a different assumption about what the numbers mean:

Method Formula within group Use for
weighted_mean weighted.mean(value, weight) rates and percentages weighted by population
mean mean(value) a simple unweighted average
sum sum(value) / sum(weight) * 100 (not an additive total; see below) a population-weighted rate expressed as a percent
proportion sum((value/100) * weight) / sum(weight_non_na) * 100 indicators given as percentages, reweighted to a population proportion
total sum(value) additive person counts (refugees, displaced persons, births), where the regional value is the sum of the country values

Two method names mislead. sum does not return a plain total; it divides the summed values by the summed weights. If you want a genuine count, the literal sum of the country figures, use total. Missing values are dropped, so a group with no reported values totals 0; set coverage_threshold if such a group should come back missing instead.

proportion reads the value column as a percentage (it divides by 100), rebuilds the number affected, and expresses that as a share of the covered population. Use it when each country reports, say, “12.4 % of children stunted” and you want a population-correct regional percentage rather than an average of country percentages.

7.1.3 Coverage and the threshold

The coverage accounting is the reason to prefer this aggregator over a hand-written group_by() |> summarise() or pandas groupby().agg(). For every group the function computes:

  • Pop_Covered: the share of the group’s total weight that sits on rows with a value. A region whose reporting countries hold 90 % of its population has Pop_Covered = 0.9; the other 10 % shows up here rather than vanishing into a falsely confident average.
  • Country_Coverage and Total_Countries: the number of distinct countries with a value, and the number of distinct countries in the group, both counted on country_id. If that column is absent, validation warns and both fall back to a row count, which overstates coverage when a country has several rows.
  • Total_Population and Data_Population: the summed weight over all rows and over rows with a value (returned only when total.population / total_population is on).
  • Number_Affected: the rebuilt count, returned only when number.affected is on and method == "proportion".

coverage_threshold turns Pop_Covered into a gate. Give it a fraction in [0, 1] and the aggregator sets Aggregate to missing for any group below it, while still returning the coverage columns so the reader can see why. The common UNICEF convention, and the value the error message suggests, is 0.5: report a regional figure only when the reporting countries hold at least half the population. With validation on, a value outside [0, 1] is an error.

The output always starts with the by columns and Aggregate, then adds the metadata columns you asked for:

# Output column order, with the default flags:
#   <by...>, Aggregate, Pop_Covered, Country_Coverage, Total_Countries

7.1.4 The global row

With global = TRUE (the default), the same calculation runs once more over the whole input, ignoring the groups, and comes back as one extra row whose by columns all hold global_label (default "WORLD"). The threshold applies to it too. Turning the global row on converts the by columns to character, so that the label fits. Set global = FALSE when you stack aggregates yourself, as dw_regions() does.

7.1.5 Validation and the error envelope

With validate on (the default), the function checks that value, weight and every by column exist. If one is missing it stops with the toolkit’s standard envelope, [cso_toolkit.aggregate_data_v2] Missing required column(s): ..., followed by the first ten data columns and a one-line fix (Appendix C). R raises it with stop(), Python with KeyError. An unknown method is refused whether or not validation is on. Set validate = FALSE on hot paths where you have already checked the schema; dw_regions() does so and runs its own checks first.

7.2 Building the standard footnote: generate_agg_footnote

Languages: R, Python. Stata: n/a. See the coverage matrix.

Coverage numbers only help if they reach the reader. generate_agg_footnote() turns them into the one-line caption that sits under aggregated tables and charts: "N/M countries (P % population coverage)", with an optional "Based on latest estimates from YYYY to YYYY." prefix and optional Exemptions: and Exclusions: suffixes.

  • R
  • Python
note <- generate_agg_footnote(
  country_coverage = 41,
  total_countries  = 48,
  pop_coverage     = 0.87,
  start_year = 2015, end_year = 2023
)
# "Based on latest estimates from 2015 to 2023. 41/48 countries (87 % population coverage)"
note = generate_agg_footnote(
    country_coverage=41,
    total_countries=48,
    pop_coverage=0.87,
    start_year=2015, end_year=2023,
)

pop_coverage is a fraction in [0, 1], printed as a whole percent. The prefix appears only when both years are given. exemptions and exclusions take country codes and append them as notes: the same codes you pass to apply_time_window(), so a windowed aggregate and its footnote agree.

7.3 Picking the latest observation: apply_time_window

Languages: R, Python. Stata: n/a. See the coverage matrix.

Most regional aggregates use the latest available estimate per country within a window. apply_time_window() makes that selection. Within each country it keeps the single row with the most recent time_col, but only if that year falls inside the inclusive window [start_year, end_year].

  • R
  • Python
latest <- apply_time_window(
  data,
  country_col = "REF_AREA",
  time_col    = "TIME_PERIOD",
  start_year  = 2015,
  end_year    = 2023,
  exemptions  = c("SOM", "YEM")   # fragile states: keep latest regardless
)
latest = apply_time_window(
    data,
    country_col="REF_AREA",
    time_col="TIME_PERIOD",
    start_year=2015,
    end_year=2023,
    exemptions=["SOM", "YEM"],
)

Two lists tune the selection. Countries in exemptions keep their latest observation even when it predates the window, the usual treatment for fragile states whose most recent survey is old but still the best available. Countries in exclusions are dropped before ranking and never reach the aggregate. The result has one row per surviving country; a country that meets neither the window nor an exemption disappears. The helper’s working columns are removed from the output, and so is any column of yours whose name starts with . (R) or _ (Python), so rename such columns first.

start_year and end_year have no defaults in either language, and in Python every argument after data is keyword-only, so pass them by name. country_col and time_col default to "REF_AREA" and "TIME_PERIOD".

7.4 Redistributing weights over missing rows: dw_nestweight

Languages: R, Python. Stata: n/a. See the coverage matrix.

When a survey value is missing on some rows, and the missingness is not completely at random within a stratum, a weighted mean over the observed rows undercounts. dw_nestweight() corrects this by reweighting. Within each stratum (the single column named in by) it scales up the weights on the observed rows so that they sum to the stratum’s total weight. The total is preserved; the mass moves onto the rows that contribute to the estimate. A stratum with no observed rows gets weight 0 throughout.

\[ \text{scale}_l = \frac{\sum_{i \in l} w_i}{\sum_{i \in l,\ v_i \text{ observed}} w_i}, \qquad w'_i = w_i \cdot \text{scale}_l \ \text{ if } v_i \text{ observed, else } 0. \]

(This ports the World Bank EduAnalyticsToolkit’s edukit_nestweight, by Diana Goldemberg.)

  • R
  • Python
adj <- dw_nestweight(
  data,
  value      = "stunting",
  by         = "stratum_id",
  weight     = "hh_weight",
  new_weight = "hh_weight_adj"
)
# adj now has hh_weight_adj; sum(hh_weight_adj) == sum(hh_weight) per stratum
adj = dw_nestweight(
    data,
    value="stunting",
    by="stratum_id",
    weight="hh_weight",
    new_weight="hh_weight_adj",
)

The function returns the input with one new column, new_weight (default "weight_adj"); it does not aggregate. Pass that column to aggregate_data_v2(weight = "hh_weight_adj", method = "weighted_mean") for the estimate itself. The details:

  • weight = NULL (R) / weight=None (Python) uses a unit weight, so the helper reduces to per-stratum counts of observed rows.
  • only takes a logical mask with one entry per row (a boolean Series in Python) that restricts which rows count as observed, for example only respondents who were asked the question.
  • Rows with a missing stratum get weight 0, with a warning.
  • A non-numeric weight column stops in R. Python coerces it to numbers, so values that cannot be converted are treated as missing and get weight 0.
  • Verbose output reports the pooled mean of value under the original and the redistributed weights, but only for a numeric value; otherwise it prints a note and skips the comparison. In R, verbose and debug follow the global options; Python has verbose only, defaulting to True.

7.5 Demographics helpers: dw_pop and dw_regions

The last two helpers wrap the population-and-regions workflow. Both fetch through dw_api_fetch, so they inherit the external-API contract exactly: a producer session may fetch and cache, a reviewer session reads the cache and never goes to the network.

7.5.1 dw_pop: population denominators

Languages: R, Python. Stata: n/a. See the coverage matrix.

dw_pop() wraps dw_api_fetch(api = "wb") for the World Bank total-population indicator SP.POP.TOTL. Every population-weighted regional mean needs a denominator; dw_pop() hides the indicator code, the cache key and the column clean-up, and returns three columns, REF_AREA, TIME_PERIOD and OBS_VALUE, sorted by country and year.

  • R
  • Python
# All countries, latest year per country
pop <- dw_pop()

# All countries, a specific year
pop_2023 <- dw_pop(year = 2023)

# A specific country list
pop_sahel <- dw_pop(countries = c("BFA", "MLI", "NER", "TCD"))
from cso_toolkit import dw_pop

pop = dw_pop()
pop_2023 = dw_pop(year=2023)
pop_sahel = dw_pop(countries=["BFA", "MLI", "NER", "TCD"])

The arguments are year (a year or several; NULL/None returns the latest year per country), indicator (default "SP.POP.TOTL"), countries (a filter on ISO3 or M49 codes; NULL/None keeps all), refresh (force a live fetch and replace the cache, producer only) and cache_key (default "wb_population_sp_pop_totl"). Both languages use the same names, defaults and cache key. The function looks for the country, year and value columns under several names (iso3c or iso2c; date or TIME_PERIOD; value, OBS_VALUE or the indicator code), because World Bank client packages have changed their columns over time, and stops with a fix if any of the three cannot be found. It drops rows missing any of the three, so sparse World Bank aggregate rows do not leak through.

7.5.2 dw_regions: UNICEF regional aggregates

Languages: R. Python: No (redesign tracked in #40); Stata: n/a. See the coverage matrix.

dw_regions() is the highest-level helper here. Give it a country-level table and it returns that table with UNICEF regional rows appended: one row per region in the taxonomy (and per by tuple), each carrying the aggregate and its coverage columns.

# Country-level tibble with INDICATOR + TIME_PERIOD + OBS_VALUE
national <- dw_use(name = "dw_ed_edu.csv", sector = "ed", kind = "wrk")

# Add population-weighted UNICEF region rows
enriched <- dw_regions(national, value = "OBS_VALUE")

# Or weight by a sector-specific column already in the data
alt <- dw_regions(national, value = "OBS_VALUE", weight = "births_under5")

It runs five steps:

  1. Resolve the country-to-region map. It fetches "<taxonomy>.csv" from the public unicef-drp/Country-and-Region-Metadata repository with dw_api_fetch(api = "github_raw"), cached as regions_<taxonomy in lower case>. The default taxonomy is UNICEF_REP_REG_GLOBAL; refresh_metadata = TRUE forces a re-fetch. The country column may be called REF_AREA, ISO3, iso3c or country_code, the region column REGION, region, REGION_CODE or UNICEF_REGION. Rows with a blank region are dropped.
  2. Attach the weight. With weight = "population" (the default), dw_pop() supplies World Bank denominators, merged on REF_AREA and TIME_PERIOD when the data has TIME_PERIOD, and on REF_AREA alone otherwise. Where the World Bank has not yet published a year, the country’s latest population fills in. Any other string names a weight column that must already be in data.
  3. Join the data to the region map. Country codes missing from the taxonomy are excluded with a warning that names them, not dropped silently.
  4. Aggregate per region with aggregate_data_v2(by = c("REGION", by), global = FALSE, validate = FALSE, method = method). There is no global row and no coverage_threshold: every regional value is returned, so check Pop_Covered before you publish one.
  5. Stack. The regional rows are made to match the input (REGION becomes REF_AREA, Aggregate becomes your value column) and appended to the original rows. Regional rows also carry the coverage columns (Pop_Covered, Country_Coverage, …), left missing on the country rows.

The arguments are data, value, weight (default "population"), method (passed to the aggregator, default "weighted_mean"), taxonomy (default "UNICEF_REP_REG_GLOBAL"), by (the grouping columns kept within each region, default c("INDICATOR", "TIME_PERIOD")) and refresh_metadata.

dw_regions adds two guards. It checks up front that REF_AREA, value and every by column are present, raising the toolkit envelope itself because it turns off the aggregator’s validation. And it refuses a value that clashes with one of the aggregator’s output names (Aggregate, Pop_Covered, Country_Coverage, Total_Countries, Total_Population, Data_Population, Number_Affected), which would otherwise fail obscurely inside the aggregator. If you hit it, rename the value column before the call.

7.6 Putting it together

The helpers chain. dw_nestweight() belongs at the survey stage, where it adjusts the weights behind each country’s estimate. Once you have one row per country and year, a regional pipeline in R reads:

latest <- apply_time_window(national, start_year = 2015, end_year = 2023,
                            exemptions = c("SOM", "YEM"))
out    <- dw_regions(latest, value = "OBS_VALUE", by = "INDICATOR")

regional <- out[!is.na(out$Pop_Covered), ]   # the appended region rows
note <- generate_agg_footnote(
  country_coverage = regional$Country_Coverage[1],
  total_countries  = regional$Total_Countries[1],
  pop_coverage     = regional$Pop_Covered[1],
  start_year = 2015, end_year = 2023,
  exemptions = c("SOM", "YEM")
)

Pass by = "INDICATOR" here. After apply_time_window() each country’s row can come from a different year, so grouping on TIME_PERIOD as well (the default) would split each region by year; the regional rows come back with TIME_PERIOD missing. The population merge still uses each country’s own year.

In Python, run apply_time_window, dw_pop and generate_agg_footnote the same way, join your own country-to-region map, and call aggregate_data_v2(..., by=["REGION", "INDICATOR"], global_=False) for the regional step.
