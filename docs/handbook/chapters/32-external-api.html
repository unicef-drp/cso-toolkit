6  The external-API contract

A reproducible analysis must re-run today and produce the numbers it produced last month, even if a statistical agency has since revised its figures, renamed an indicator or gone down for maintenance. Most analytics code reaches for live data with bare calls to jsonlite::fromJSON(), rsdmx::readSDMX(), wbstats::wb_data(), httr::GET(), requests.get() or wbgapi. Each such call depends silently on the network and on whatever the server happens to serve at that moment. The external-API contract removes that dependency. It gives every consumer of cso-toolkit one mode-aware wrapper that fetches once, freezes the result to a provenance-stamped cache, and reads from the frozen copy thereafter.

Two session modes govern the network. A producer session may hit the live API and populate the cache; a reviewer session reads the frozen cache and may not touch the network at all. The Database Manager, the producer who owns the deposit, decides when each cache is refreshed. Roles and the mode contract defines the roles; this chapter shows how the API wrapper enforces them.

6.1 Why a wrapper at all

A direct API call ties together three concerns that belong apart: what you want (an indicator, a codelist, a flow), how you reach it (the package, the URL shape, the authentication), and when it was last retrieved. The wrapper separates them. You name the source with a short api = string and the result with a stable cache_key. The wrapper picks the right package, builds the URL, writes the result to disk and records where it came from. A sector script stops being a tangle of bespoke HTTP and becomes a list of named fetches. In DW-Production, fourteen hand-coded SDMX codelist requests became a small manifest table and one loop over dw_api_fetch(api = "sdmx_codelist", ...).

6.2 The three entry points

dw_api_fetch(api, cache_key, ...) does the work. It checks the cache first; on a miss it either fetches live (producer) or stops (reviewer). Besides api and cache_key it takes refresh, ext, metadata and takeover (the last only matters in multi-producer projects), and passes every other argument to the fetcher for that source.

Languages: R, Python. Stata: Route via R or Python. See the coverage matrix.

dw_api_cached(api, cache_key, ext = "csv") reads a cache and never touches the network, whatever the mode. It reads only the canonical root (teamsRawDataCanonical), never the reviewer sandbox. Its ext defaults to "csv", not to the source’s default format, so a cache stored as RDS or pickle needs ext = "rds" (R) or ext="pkl" (Python). A missing cache stops in R and raises FileNotFoundError in Python; the message says that an ext mismatch is a common cause.

Languages: R, Python. Stata: Route via R or Python. See the coverage matrix.

dw_api_inventory(api = NULL) lists what has been cached, so the Database Manager can audit freshness (see Auditing what is cached below).

Languages: R, Python. Stata: Route via R or Python. See the coverage matrix.

# Fetch (or read the cache): one named source, one stable cache key.
entrance_age_primary <- dw_api_fetch(
  api       = "uis",
  endpoint  = "indicators",
  params    = list(indicator = "299905"),
  cache_key = "uis_entrance_age_primary"
)

# Cache-only read; never hits the network, stops if absent.
lp <- dw_api_cached(api = "wb", cache_key = "wb_learning_poverty_primary")

# What is already cached?
dw_api_inventory("wb")

6.3 The mode contract, applied to the network

dw_api_fetch has no mode = argument. The session decides. Before it reaches the network the wrapper tests dw_apis_allowed, which the profile sets to true exactly when dw_mode is producer; Profiles and the mode switch shows where both come from. A standalone Python example that skips the profile has to set dw_apis_allowed=True itself, as the worked example below does.

Session Cache state Action
Producer cache present, refresh = FALSE reads the cache
Producer cache missing or refresh = TRUE hits the live API, writes the cache through dw_save, returns the result
Reviewer cache present, refresh = FALSE reads the cache
Reviewer cache missing or refresh = TRUE stops with the [cso_toolkit.dw_api] Reviewer mode forbids live API calls. envelope (stop() in R, PermissionError in Python)

The cache lookup has two tiers. On a call without refresh, the wrapper looks in the producer sandbox (teamsRawData) first and then in the canonical deposit (teamsRawDataCanonical), so a reviewer reads the frozen deposit even when no sandbox copy exists. The IO contract introduces both roots.

refresh = TRUE is the producer’s way to re-pull a source on purpose. It skips the lookup, fetches live and replaces the existing cache; the wrapper passes the overwrite confirmation to dw_save for you. In a reviewer session the same call stops; when a cache exists, the envelope’s Reason line says the refresh was refused (refresh requested; the cache at <path> is read without refresh), and otherwise that the cache is missing. In a multi-producer project, a refresh that replaces another user’s fetch says so and keeps that fetch’s sha256, user and fetched_at as metadata.previous_fetch in the new sidecar (Appendix B).

The lockout message names the call, the path it expected and two ways forward: check that the Database Manager has populated the canonical cache, or, if you are the producer, switch the session to producer mode. A script that reaches a remote outside the wrapper should call the reviewer gate dw_require_no_api() first; it is described in Profiles and the mode switch.

6.4 The supported sources

The wrapper dispatches on the api = string:

api = Source R Python Default cache format
"uis" UNESCO UIS indicators and generic JSON endpoints Yes Yes .csv
"sdmx" Generic SDMX data, any provider and flow Yes Yes .csv
"sdmx_codelist" UNICEF SDMX codelist as (code, name, description) Yes Yes .csv
"wb" World Bank WDI indicators Yes Yes .csv
"wb_indicators" World Bank indicator catalogue Yes Yes .rds (R) / .pkl (Python)
"ilo" ILO SDMX Yes Yes .csv
"unsd_sdg" UNSD SDG API (form-encoded POST of series codes) Yes Yes .csv
"github_raw" Pinned-commit raw.githubusercontent.com file Yes Yes .rds (R) / .pkl (Python)
"http" Generic HTTP GET returning text Yes Yes .rds (R) / .pkl (Python)
"json_get" Generic JSON GET returning a parsed object Yes Yes .rds (R) / .pkl (Python)
"csv" Flat CSV at a URL (SDMX REST-CSV, Data360 files, ILOSTAT format=.csv) Yes Yes .csv

11 keys; Stata has no external-API wrapper and reads the cache with dw_use.

Each source has a thin internal fetcher that loads its package only when that source is fetched, so a repository that never touches SDMX needs neither rsdmx nor sdmx1. The arguments that matter per source:

api = Key arguments (defaults) R package Python package
"uis" endpoint ("indicators"), params jsonlite requests
"sdmx" providerId, flowRef, key, version (R "1.0"; Python: in flowRef), start, end rsdmx sdmx1
"sdmx_codelist" agency, codelist, version ("1.0") httr, tibble requests
"wb" indicator, start_date (2000), end_date (current year) wbstats wbgapi
"wb_indicators" none wbstats wbgapi
"ilo" flowRef, key, start, end rsdmx sdmx1
"unsd_sdg" series_codes, endpoint (the UNSD Series/DataCSV URL) httr, readr requests
"github_raw" owner_repo, ref ("main"), path readr requests
"http" url, headers httr requests
"json_get" url jsonlite requests
"csv" url readr requests, pandas

For github_raw, pin ref to a tag or commit when the file must not change under you; "main" follows the branch. The file’s extension decides how it is parsed: .csv, .tsv and .json become a table or a parsed object, anything else a vector of lines.

The two languages differ in what happens to extra arguments. R passes them through ... to the underlying call (httr::GET(), readr::read_csv(), rsdmx::readSDMX() and so on). Python’s fetchers ignore keywords they do not name, except csv, which passes them to pandas.read_csv(). Python’s HTTP fetchers take a timeout in seconds (dw_api_fetch(..., timeout = 600)), with a default per source of 60 to 300 seconds; R relies on the package’s own. If a Python fetcher fails on a missing or wrong argument, dw_api_fetch re-raises the TypeError or KeyError as a RuntimeError that names the cache key and the arguments. sdmx1 takes a dataflow version only inside flowRef ("AGENCY,FLOW,VERSION"), so the Python sdmx fetcher warns, rather than sending it, when version is given separately. The World Bank sources call different clients (wbstats in R, wbgapi in Python); the Python fetcher reshapes wbgapi’s result to the layout wbstats gives, one row per country and year with iso3c, country, date and a column per indicator, so dw_pop() reads a wb cache written by either language.

Sources whose results do not flatten into a table (nested JSON, plain text, list-columns, arbitrary files) default to RDS in R and pickle in Python, as the table above shows. Pass ext = to override the default, for example to keep a UIS response that is not flat:

6.5 The cache and its provenance

Every fetch writes two files, at a fixed place keyed by api and cache_key:

<rawdata>/_apis/<api>/<cache_key>.<ext>
<rawdata>/_apis/<api>/<cache_key>.<ext>.provenance.json

The cache_key is the file name, so make it readable snake_case that carries the distinguishing parameters: wb_learning_poverty_primary or sdmx_codelist_UNICEF_CL_RESIDENCE_1_0, not a hash. The wrapper writes the cache through dw_save and reads it back through dw_use, so the cache inherits the mode-aware write path, the Z: mirror when the drive is mapped, and the standard .provenance.json sidecar (The IO contract; fields in Appendix B).

To the sidecar’s standard fields, dw_api_fetch adds a metadata block that records how the cache was obtained:

"metadata": {
  "api": "sdmx_codelist",
  "cache_key": "sdmx_codelist_UNICEF_CL_RESIDENCE_1_0",
  "fetched_at": "2026-05-25T14:23:11+0000",
  "elapsed_secs": 0.412,
  "refresh_flag": false,
  "fetch_args": {"agency": "UNICEF", "codelist": "CL_RESIDENCE", "version": "1.0"}
}

fetch_args lets a reviewer, or a later producer, see exactly which parameters produced the frozen result. fetched_at and elapsed_secs give its age and its cost, and refresh_flag says whether it was a first fetch or a deliberate re-pull. Whatever you pass as metadata = is merged on top, which is how a load-bearing fetch carries a reason, a ticket or a vintage into the sidecar.

The two languages treat credentials differently. Python replaces the value of any fetch_args key whose name looks sensitive (it contains token, auth, password, secret, api_key, headers, cookie, bearer or a similar substring) with "<redacted>" before the sidecar is written. R stores fetch_args as passed, so a credential you pass through ... in R ends up in the sidecar.

Caches never expire on their own. A refresh is always an explicit refresh = TRUE, and the Database Manager owns the cadence for each cache.

A CSV cache is an ordinary CSV file, so a Stata script reads it like any other, with dw_use:

dw_use, filename("wb_learning_poverty_primary.csv") path("$teamsRawData/_apis/wb")

6.6 Auditing what is cached

dw_api_inventory walks teamsRawDataCanonical/_apis/, skips the sidecars, and returns one row per cache file with the columns api, cache_key, ext, size_bytes, mtime and fetched_at. It takes fetched_at from the sidecar’s metadata (falling back to written_at), so stale caches stand out. It lists the canonical root only, and returns an empty frame when nothing is cached there.

6.7 When a live fetch fails

A live fetch can fail for reasons that have nothing to do with your code. In Python every fetcher goes through one HTTP helper that turns a timeout into TimeoutError, a connection failure into ConnectionError and an HTTP error status into RuntimeError. Each message carries the method, the URL and a fix; the status error adds the code and the first 300 characters of the response body. R fetchers raise the underlying package’s error (for example from httr::stop_for_status()), without the [cso_toolkit.*] prefix. Appendix C shows the messages and how to tell a blocked call from a failed one.

WarningAPI failures are about the network, not your cache_key

A timeout or a 403 can only happen on a live fetch: in producer mode, on a cache miss or with refresh = TRUE. A reviewer never sees one, because a reviewer never reaches the network. A recurring burst of 403s from the UNICEF SDMX endpoint is an upstream rate limit, not a wrapper bug. Retry later or from a different network, then commit the frozen cache.

6.8 Migrating a sector script

Adopt the contract one call at a time:

  1. Find each raw API call: fromJSON, readSDMX, wbstats::wb_data and httr::GET/POST in R; requests.get, httpx.get, sdmx.Client and wbgapi calls in Python.
  2. Pick the matching api = value from the tables above.
  3. Choose a stable, descriptive snake_case cache_key that carries the distinguishing parameters. It becomes the file name.
  4. Replace the call with dw_api_fetch(api = ..., cache_key = ..., ...). Give load-bearing fetches a metadata = argument (a reason, a ticket, a vintage) so that context reaches the sidecar.
  5. Run once in producer mode to populate the cache.
  6. Open a pull request. The script passes when a reviewer session can run it end to end from the cache with no network access.

The contract auditor confirms that no raw network calls remain; it and its place in CI are described in Checks and CI.
